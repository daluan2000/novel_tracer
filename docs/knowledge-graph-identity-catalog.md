# 全书身份目录：实现与验收

更新：2026-11-24。规则版本 5，SQLite Schema 4。

## 数据与流程

`原文窗口 → 提及与事实候选 → 全书身份目录 → 具体提及绑定 → 身份及所属复核 → 关系回填与筛选 → 原子发布`

- `inventory.py` 收集按类型和原文绝对位置标识的提及，保留独立上下文、身份线索及事实候选。不同窗口不会为同一处提及重复计数。多锚点旧响应保留端点备选，不随意选第一个锚点。
- `catalog.py` 汇总带章节位置的名称卡片。全名与名、名字加称呼、相近姓名和抽取身份线索用于有界候选召回，不能直接证明同一身份；目录请求最多16个名称，跨章证据保留介绍、同名提示及分布样本。
- 模型目录声明包含原文身份锚点、规范名称、名称类别、可选姓与名和引用依据。无依据的额外别名被剔除，不能连带删除有原文依据的身份；遗漏的输入名称锚点由服务端定位补齐，不合成引文。原文明确的“姓…名…”介绍可保留被模型遗漏的独立身份。
- 同名、同类和名称片段相似只产生候选。一个名称可映射多个身份，绑定以具体原文场景为准。姓、名组成的全名只有在输入中实际出现且具有唯一原文锚点时才用于规范名称对齐。
- 目录最多两轮定向复核，可重算身份归属；合法共享称呼交给提及绑定，不反复强迫合成一个人物。名称相同的独立身份与全名/名分裂分别检查。
- 绑定每批最多16处。姓名中的家庭所属指代与首次结果冲突时，只作为定向复核提示，不把寄居与姓氏等同。复核无结果则恢复为待确认，不保留原先的可疑结论。
- 目录复核和所属指代复核均使用 `NOVEL_AGENT_GRAPH_RESOLUTION_CONCURRENCY`（默认4）。目录复核只并发名称及涉及身份的全部名称形式互不重叠的组，按原组序提交；重叠组等待前面结果生效后再判断是否复核、构造输入，保持串行检查点哈希兼容。所属指代复核逐处独立请求，并发返回后统一按原序写入绑定。
- 正式名称形式和别名只公布实际提及绑定支持的用法。例如“宝玉哥哥”不会仅凭候选召回进入甄宝玉的正式别名。
- 关系候选保留类型、方向、陈述方式、肯否及原文证据；身份目录冻结后回填端点。未绑定端点的事实保持待确认，低价值实体按归一后的独立提及数和剧情重要性筛选。

## 持久化与接口

新增 `graph_source_mentions`（含绑定状态、候选、原文）、`graph_identity_decisions`（原始提议、接受/拒绝及服务端补齐的锚点）、`graph_fact_candidates`。原有正式图表保留，Schema 1/2 自动增量升级到3，保留旧已发布版本。

目录、绑定和复核使用独立检查点与输入哈希。有效模型响应先落盘；目录超限可缩小证据卡，绑定可二分，恢复不重发已有成功请求。发布前校验已归属提及确有正式实体及关系引用完整性。

现有搜索、邻居、路径、关系证据和 Agent 接口继续使用规范实体。实体详情额外返回名称类别、姓与名，以及可回读的身份依据。

新增 `GET /api/novels/{novel_id}/graph/unresolved?version=...&offset=0&limit=20`，支持原有章节范围参数，返回待确认提及、候选、原因及原文。旧版本和跨书章节沿用现有校验。前端显示目录/绑定/复核进度，待确认记录按需分页，切书、过滤或版本变化会丢弃旧响应。

旧图仍可查询；应用新生成规则需使用现有重建入口。旧格式检查点不直接转换为新目录。生产流程不读取小说专属人物白名单或评估标签。

## 人工修正与统一历史

`graph_revisions` 保存快照的父版本、操作类型、恢复来源、生效的人工合并集合及原始构建任务；`graph_build_bases` 在构建或续跑开始时固定其父版本和待沿用的修正。启动时将 Schema 1–3 原子迁移到4，为已有已发布图谱补齐历史。人工版本复制完整图谱、身份记录及事实候选，不复制模型请求或伪造构建任务。

合并预览不创建版本。执行合并时保留选中的目标实体及名称、描述和姓名信息，汇总别名、名称形式、身份依据及提及；同步重定向绑定、候选及事实端点。同类型同方向同肯否同陈述方式的关系聚合证据，对称关系规范端点；自关联只从正式关系中过滤，原始事实候选及旧快照保留。待确认提及即使只剩一个候选也不自动确认为该实体。

写操作在同一事务中复制、修改、校验、记录历史并切换当前版本；预期当前版本过期返回409，构建排队、运行及停止收尾期间拒绝写入。恢复任何兼容的已发布历史版本时创建新快照，父版本指向恢复前的当前版本，恢复来源另行记录；其修正集合完全继承恢复目标，其他历史分支不删除。Agent 已固定的旧快照继续可读。

人工规则通过基准快照中的全部原文提及位置及类型匹配新模型结果，要求每一侧提及都存在且归属于同一个明确实体，并且候选没有吸收基准快照中的其他身份。不同实体则应用合并，已经属于同一实体则标记已满足；缺失、拆分、混入其他身份或正文身份变化则保留模型结果，记录待确认原因。重新指定双方会替换旧规则；跳过仅对当前快照生效，今后重建仍会尝试匹配。

接口均位于 `/api/novels/{novel_id}/graph`：

| 接口 | 行为 |
|---|---|
| `POST /merges/preview`、`POST /merges` | 请求含 `version`、`source_id`、`target_id`，可选 `replaces_correction_id`；预览或执行合并 |
| `GET /history?offset=0&limit=20` | 分页历史，含操作来源、数量、当前标记及能否恢复 |
| `POST /history/{target_version}/restore` | 请求含预期当前 `version`，恢复指定快照 |
| `GET /corrections?version=...` | 查询当前快照的人工规则及应用状态 |
| `POST /corrections/{id}/skip` | 请求含预期当前 `version`，生成跳过本次应用的新快照 |

状态接口新增 `revision.operation` 和 `revision.pending_corrections`。人工合并、恢复和跳过均不增加模型用量，构建详情继续展示实际构建任务的请求记录。

## 真实模型小样

标注文件 `tests/fixtures/red_chamber_identity.json` 包含来自本地《红楼梦》原文的500处人物提及，跨78章、30个身份，以及100条事实候选端点。原文位置与引文经原书核验，特别标注甄贾宝玉、袭人的旧名“珍珠”与后文另一位珍珠。

模型输入不包含身份标准答案。事实谓词沿用既有抽取候选，验收只评价端点身份归属及证据保留，不把它当作关系语义准确率。

使用项目配置的 `qwen3.7-flash`，数据仅送往 `https://maas.qianwenaiapi.com`；运行于独立临时数据库，没有重建或改写用户的已发布图谱。最终报告：`tmp/identity-eval-i_o_6tqv/report.json`。

| 指标 | 本次结果 |
|---|---:|
| 已归属提及覆盖 | 500/500 |
| 已归属提及准确率 | 100% |
| B³ 聚类精确率 / 召回率 | 100% / 100% |
| 误合并簇 / 分裂身份 | 0 / 0 |
| 事实候选端点归属 | 100/100 |
| 林黛玉相关提及 | 35处，1个规范节点 |
| 贾宝玉相关提及 | 45处，1个规范节点 |
| 甄宝玉相关提及 | 6处，1个独立节点 |

“黛玉”“林黛玉”“林妹妹”均指向林黛玉；“宝玉哥哥”仅指向贾宝玉；“宝玉”依原文分别指向甄、贾两人。

开发期间累计94次真实请求，含格式纠错、失败试验、针对性修复和检查点复用；报告的 token 与耗时是累计调试消耗，不能当作单次生产构建成本。预算阻止的本地尝试未发送到服务商。最终有效流程保留32个检查点，已导出录制文件 `red_chamber_catalog_recording.json`，自动化回归可离线重放并校验这500处提及。

这些样本用于本轮开发与调试，尚无独立留出集或整本新版本图谱的验收；不能外推为全书或其他小说100%准确。

## 验证命令

最终后端完整回归261项通过（含真实模型录制回放），前端47项通过，TypeScript检查与Vite生产构建通过。中途遇到过 Windows 临时上传目录重命名的间歇性权限错误，使用新的短临时路径完整复测通过；没有为绕过测试而改变产品上传行为。

```powershell
# 完整回归：新身份管线及真实模型录制回放均不联网
python -X utf8 -m pytest

# 仅检查样本规模
python -X utf8 scripts/evaluate_identity_catalog.py

# 显式执行真实模型小样；用 --resume-dir tmp/identity-eval-... 复用成功响应
python -X utf8 scripts/evaluate_identity_catalog.py --run-model --max-requests 60

# 无网络身份目录性能基准
python -X utf8 scripts/benchmark_graph_resolution.py --delay 0.01
```

模拟4个人物、每人65处提及，只需4次目录请求，保留全部260处提及；同指纹检查点重放无需新模型请求。该结果说明请求粒度的变化，不预测真实供应商耗时或语义质量。
