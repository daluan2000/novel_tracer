# 小说图知识库需求文档 V1

- 文档状态：需求基线，待后续功能开发。
- 日期：2026-11-18。
- 开发分支：`feat/novel-knowledge-graph`。

## 一、目标与范围

在现有小说解析、文本检索和 Agent 问答基础上，增加按小说独立构建的图知识库。将小说中的重要实体提取为节点，将原文支持的语义关系提取为边，支持关系浏览、关系路径检索和基于图谱的问答。

“关键词”在本功能中指具有明确意义的实体，例如人物、地点、组织、物品、功法。普通分词结果、词频及共同出现次数不直接作为语义关系。

典型场景：

- 搜索某个人物，查看其师承、所属组织、持有物品及相关人物。
- 查询两个人物之间通过哪些实体和关系产生联系。
- 限定章节范围，查看该范围原文中出现的关系与证据。
- 提问“甲与乙有什么联系”，Agent 使用图谱寻找线索，结合原文生成带引用的答案。

首版已确认的边界：

- 每本小说独立建图，不跨书合并或检索。
- 用户手动触发大模型后台构建。
- 同时提供可视化图谱和 Agent 检索能力。
- 使用本地 SQLite，无需部署额外数据库服务。
- 保留章节中的不同关系陈述；暂不提供人工编辑、剧情时序推断和当前关系状态判定。

## 二、功能需求

### 2.1 图谱构建与管理

- 上传小说后，沿用现有解析流程；用户进入“知识图谱”页，点击“构建图谱”后开始处理全书。
- 构建前展示模型名称、待处理文本规模，以及正文将发送给已配置模型服务的说明。首版复用现有聊天模型配置。
- 基于已有文本块分批抽取，提供相邻上下文以减少跨块关系遗漏；抽取结果必须映射回现有章节与原文位置。
- 后台显示等待、处理中、已完成、失败、已停止等状态，以及已处理/总批次数、实体数、关系数、耗时和模型用量。供应商未报告的 token 用量标记为未知。
- 支持停止、失败后重试和服务重启后手动继续；已完成批次持久化，继续时复用与当前构建版本匹配的结果。
- 同一本小说的重复构建请求不启动重复任务；首版全局同时执行一个图谱构建任务。
- 已发布图谱继续可查；重建结果全部完成后整体替换。首次构建完成前不开放部分图谱检索。
- 图谱构建失败、停止或不可用时，原有文本检索和问答仍可使用，不自动触发重新构建。

### 2.2 实体与关系抽取

| 对象 | 首版要求 |
|---|---|
| 实体 | 支持人物、地点、组织、物品、功法、其他专有概念 |
| 实体属性 | 名称、类型、别名、原文出现位置 |
| 关系 | 有类型的“来源实体—关系—目标实体”，保留方向 |
| 关系示例 | 师徒、亲属、隶属、位于、持有、使用、合作、敌对 |
| 关系证据 | 原文引文、章节、文本块、行号与字符位置 |

具体规则：

- 使用统一关系词表，将同义表达规范化；首版不开放用户自定义实体类型和关系类型。
- 相同实体的重复出现需要归并；只有存在明确上下文依据时才合并别名。
- 同名异人、含糊称谓和指代无法可靠消歧时保留区分，不强行合并。
- 同一关系的不同原文依据合并为多条证据，不因重复出现生成大量重复边。
- 不同章节中的冲突或变化陈述并存，显示各自来源，不自动选定某条为最终事实。
- 每条对外可检索的关系至少有一条通过原文位置和逐字引文校验的证据；校验失败的候选不进入正式图谱。
- 引文校验只能证明原文存在，不能证明模型理解一定正确。页面将关系标明为自动抽取结果，不显示未经校准的概率评分。

### 2.3 关系图检索与展示

在现有工作台新增“知识图谱”标签页，提供构建状态、实体搜索、关系图、结果列表和证据详情。

- **实体检索**：支持名称、别名和名称片段匹配，优先展示精确匹配；重名时列出候选及出现位置供用户选择。
- **邻居检索**：选定实体后查看直接关联实体与关系，默认展开一跳，可继续扩展，最多三跳。
- **路径检索**：选择两个实体，返回最短的若干条关联路径；最多三跳、最多五条路径，保留每条边的语义方向。
- **条件过滤**：支持实体类型、关系类型、章节起止范围。
- **证据回读**：点击关系查看原文引文，并通过已有上下文读取能力展开正文。
- **交互操作**：支持缩放、拖动、节点选择和重置视图；同时提供列表，便于阅读密集结果。
- **结果控制**：单次图视图最多展示一百个节点、二百条边；达到上限时明确提示截断，引导缩小范围。

章节过滤按证据所在章节生效，使用已有解析后的章节顺序；无可靠章节标题时沿用现有分段结构。筛选结果只表示“该范围内有这些陈述”，不代表人物在某个剧情时点的真实状态，也不保证消除后文别名带来的剧透。

未找到路径时提示“在当前图谱、范围及跳数内未找到”，不能据此断言不存在关系。多跳连通不自动产生新的事实关系。

### 2.4 Agent 集成

- 为 Agent 增加实体搜索、关联关系查询和路径查询三类只读工具，复用与图谱页面相同的查询服务。
- 图谱就绪时，Agent 可根据问题选择图检索或现有文本检索；图谱不可用时继续使用原有工具。
- 图检索返回实体、关系、路径及有上限的原文证据，不向模型发送整张图。
- 图谱结果提供调查线索；最终答案中的事实引用仍需经过现有原文证据校验。
- 不把“甲认识乙、乙隶属某组织”推断成“甲隶属该组织”。
- 工具调用纳入现有步骤预算、重复调用控制和执行时间线，并记录所使用的图谱版本。

## 三、数据与接口要求

图谱是从小说派生的独立索引，不改变原始 TXT、章节或文本块标识。

本地持久化至少包含实体、别名、关系、证据、构建批次及版本信息。记录正文哈希、解析版本、抽取规则版本和模型名称，用于判断已有结果能否复用。无效或损坏的图谱应隔离并提示重建，不阻断小说加载。

在现有 `/api/novels/{novel_id}` 下增加以下能力：

| 接口能力 | 输入与输出要求 |
|---|---|
| 构建管理 | 启动、继续、重建、停止；返回任务标识及状态 |
| 状态查询 | 当前可用版本、构建进度、统计、用量和安全错误信息 |
| 实体搜索与详情 | 搜索词、类型、分页；返回实体、别名和出现位置 |
| 关联查询 | 实体、跳数、类型及章节过滤；返回节点、关系、证据和截断标记 |
| 路径查询 | 两个实体及过滤条件；返回路径与逐边证据 |

所有查询必须校验实体和章节属于当前小说。响应携带图谱版本；用户展开旧版本结果时若版本已失效，提示刷新，避免混用新旧节点。现有文本检索接口保持兼容。

## 四、验收标准

使用人工编写、带标准答案的短篇测试文本验证业务正确性；自动化测试使用固定模型响应，不依赖线上模型。

| 场景 | 通过条件 |
|---|---|
| 实体及别名 | 明确别名正确归并，同名不同人物保持区分 |
| 关系抽取 | 标准案例中的关系类型、方向和证据位置正确 |
| 证据有效性 | 所有正式关系都有可定位的有效引文；伪造引文被拒绝 |
| 跨块与重复 | 跨块上下文案例能提取关系，重复抽取不产生重复边 |
| 邻居及路径 | 一至三跳、环、无路径、方向及结果上限处理正确 |
| 章节过滤 | 返回关系在指定范围内至少有一条证据，详情不夹带范围外引文 |
| 冲突陈述 | 不同章节的冲突关系均可追溯，不被覆盖成唯一结论 |
| 构建可靠性 | 重复点击、停止、失败继续、重启恢复及重建替换符合约定 |
| Agent 问答 | 能使用图谱找到关系线索，并给出通过现有校验的原文引用 |
| 隔离与兼容 | 不串书；图谱故障不影响原有文本检索与问答 |
| 前端交互 | 构建、空结果、重名选择、截断、切书及版本失效状态清晰 |

另使用不少于二十个实体归并案例、三十条人工标注关系进行真实模型试验，报告关系准确率、召回率、错误归并和构建消耗。其结果用于评估默认模型是否可用，不将上述固定响应测试当作真实抽取质量证明。

图查询在已加载图谱时不调用大模型。性能验收使用一万节点、五万条边的合成数据，在记录配置的本地环境测量；实体搜索及一跳查询 P95 不超过一秒，三跳路径查询 P95 不超过三秒。全书构建耗时取决于文本规模和供应商，首版不承诺固定完成时间。
