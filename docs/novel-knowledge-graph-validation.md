## 超时及异常长输出修复

实际失败任务在前四批完成后，同一片段两次触及 120 秒超时；服务商日志分别记录约 1.98 万输出 token，客户端未取得完整响应与 usage。修复包含：

- 图谱独立输出上限默认 6144 token；通过模拟 HTTP 请求验证 Qwen 请求体使用 `max_tokens`，避免 SDK 将参数改写为兼容网关不一定支持的 `max_completion_tokens`。
- 识别响应 `finish_reason=length` 和 SDK 长度截断异常，直接缩小抽取窗口，不重复对截断 JSON 做格式重试；有 usage 的截断响应仍保存真实用量。
- 较大抽取窗口超时后自动二分；较小窗口和实体消歧超时采用有限重试，停止标记在重试前生效。两个子窗口与父窗口状态一起持久化。
- 图谱独立超时默认取 180 秒与聊天请求超时的较大值，输出上限与重试次数可配置；这些运行预算不改变构建指纹。
- 旧超时任务继续时优先缩小失败的待处理片段；已完成批次不重复发送。只读核验实际任务仍有四个已完成批次，旧指纹与修复后代码匹配。
- 失败请求保存耗时与安全分类；未返回用量的历史超时请求继续显示未知，不从服务商截图推算或伪造客户端统计。

新增回归验证了超时拆分、返回长度截断、SDK 截断异常、有限重试、停止中断重试、旧任务兼容、预算边界和 Qwen 实际 HTTP 请求体。前端验证了未知用量说明及“继续构建”操作。全量回归的临时目录使用较短路径，避免 Windows 260 字符路径限制影响带正文哈希的向量缓存文件。

## 合成图性能

使用 `scripts/benchmark_knowledge_graph.py --iterations 100`。数据为一万节点、五万条边，包含 1000 条边的高连接度节点、多个别名与断开的连通分量；每类查询预热后测量 100 次。环境为 Windows、Python 3.13.5、AMD64、16 个逻辑 CPU。结果用于本地查询性能验证，不代表抽取质量。

| 查询 | P50 | P95 | 截断情况 |
|---|---:|---:|---|
| 实体搜索 | 4.39ms | 5.08ms | 无 |
| 一跳邻居 | 3.69ms | 4.68ms | 1 次达到节点上限，其余完整 |
| 高连接度节点一跳邻居 | 10.80ms | 13.29ms | 100 次均按 100 节点上限截断 |
| 最多三跳的最短路径 | 9.37ms | 89.21ms | 83 次达到五条路径上限，2 次达到搜索预算，15 次完整 |
| 跨断开分量查询 | 8.17ms | 144.29ms | 15 次达到搜索预算，85 次完整；均未返回路径 |

以上延迟均满足需求目标。搜索预算耗尽时返回 `search_complete=false`，不能据此宣称已证明没有路径。高连接度结果截断是界面与输出预算的正常行为。

本次 JSON 原始报告保存在生成目录 `tmp/graph-benchmark-ailiksre/report.json`，该目录不提交到 Git。脚本会输出每次报告的实际路径，便于重新测量。

## 真实模型评估

尚未运行真实供应商质量评估，因此不声称已验证实际小说的实体归并准确率、关系准确率、召回率或构建费用。评估数据为人工编写，不包含外部小说原文。

```powershell
# 仅查看评估数据规模，不调用模型
python -X utf8 scripts/evaluate_knowledge_graph.py

# 显式启用真实模型评估，会产生模型请求与用量
python -X utf8 scripts/evaluate_knowledge_graph.py --run-model
```

启用后复用当前聊天模型配置，在独立临时目录构建参考案例，生成逐案例结果、关系准确率/召回率、归并准确率、模型身份、数据集哈希、耗时和用量报告。自动化通过和合成图性能不能替代这一评估。
