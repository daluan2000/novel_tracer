## 超时及异常长输出修复

实际失败任务在前四批完成后，同一片段两次触及 120 秒超时；服务商日志分别记录约 1.98 万输出 token，客户端未取得完整响应与 usage。修复包含：

- 图谱独立输出上限默认 6144 token；通过模拟 HTTP 请求验证 Qwen 请求体使用 `max_tokens`，避免 SDK 将参数改写为兼容网关不一定支持的 `max_completion_tokens`。
- 识别响应 `finish_reason=length` 和 SDK 长度截断异常，直接缩小抽取窗口，不重复对截断 JSON 做格式重试；有 usage 的截断响应仍保存真实用量。
- 较大抽取窗口超时后自动二分；较小窗口和实体消歧超时采用有限重试，停止标记在重试前生效。两个子窗口与父窗口状态一起持久化。
- 图谱独立超时默认取 180 秒与聊天请求超时的较大值，输出上限与重试次数可配置；这些运行预算不改变构建指纹。
- 旧超时任务继续时优先缩小失败的待处理片段；已完成批次不重复发送。只读核验实际任务仍有四个已完成批次，旧指纹与修复后代码匹配。
- 失败请求保存耗时与安全分类；未返回用量的历史超时请求继续显示未知，不从服务商截图推算或伪造客户端统计。

新增回归验证了超时拆分、返回长度截断、SDK 截断异常、有限重试、停止中断重试、旧任务兼容、预算边界和 Qwen 实际 HTTP 请求体。前端验证了未知用量说明及“继续构建”操作。全量回归的临时目录使用较短路径，避免 Windows 260 字符路径限制影响带正文哈希的向量缓存文件。

### 密集名录触发无效拆分

后续任务在抽取 35/429 时停止。最后一次模型请求正常返回，输出 2146 token；失败单位为 258 字的神仙名录。程序将候选数量阈值当作硬性失败条件，试图把不足 400 字的精简窗口继续拆分，触发 `extraction_capacity_exceeded`，被归为笼统的 graph_build_failed。

修复后，容量作为校验后正文去重候选的拆分参考，最小窗口完整返回时保留全部有效候选并提示密集。新增 Schema 候选缓存，覆盖模型返回成功、本地处理失败、修复后继续无需重发的路径；无效缓存不触发新的模型请求。后台记录安全的异常类型与调用位置，前端区分本地处理异常、候选密集和模型请求错误。

新增自动化案例包括 258 字片段含 32 个精简实体、81 个普通格式实体，全部有效候选均保留并可完成发布；重复事实与纯上下文实体不引发密度误判；本地处理故障恢复时模型调用次数保持 1 次。实际任务仅做只读核验，35 个已完成批次仍在，构建指纹匹配，可以继续。本次修复验证未发送新的真实模型请求。

## 2026-11-23 实体筛选与身份合并优化

分支 `fix/knowledge-graph-quality`。只读回放《红楼梦》现有检查点，复现 2,239 个实体、3,330 条关系。437 个物品节点中有 393 个只有一处已记录提及；抽取实际耗时约 435.6 秒、消歧约 1,449.5 秒，消歧共 6,736 次请求。

定位到错误身份依据“宝玉因让‘林妹妹吃茶’”以及“宝玉道：‘姑苏林黛玉。’”。旧逻辑仅校验引用存在，误将对话和共同出现当成同一身份，并通过别名链扩大污染。新规则在消歧前筛选低价值实体，异名合并同时要求原始名称间明确身份谓词和模型确认，传递合并保留明确异人约束；同名不确定不再强制复用。

新增自动化用例覆盖普通/精简格式的重要性证据、重叠窗口与嵌套别名计数、低频背景实体移除、关键线索保留、真实错误引文、传递合并冲突、批内引用、无效判定、容量二分、停止及检查点重放。状态接口及前端显示按类型筛选数量和身份诊断。规则版本升级为 4，已有图谱继续可读，须通过现有入口重建才能应用；没有写入实际图谱数据库或启动真实模型请求。

消歧进度单位改为单事务批量准备，已完成判定及预测在构建恢复时一次加载；模型响应与逐条预测先持久化，再应用合并。端到端基准按默认 150ms 模拟请求延迟独立运行：1 路 8.49 秒、4 路 3.10 秒，均为 40 次请求、8 个实体；抽取和消歧阶段分别约 2.75×、2.89×。报告位于 `tmp/graph-concurrency-2f39b6c7/report.json`。较短的 100ms 模拟延迟试验中，磁盘及调度开销使部分阶段未达到旧基准的 2.5× 断言；不能据此承诺不同机器和延迟下固定的并发加速比。

### 查询基准

使用 `scripts/benchmark_knowledge_graph.py --iterations 100`。数据为一万节点、五万条边，包含 1000 条边的高连接度节点、多个别名与断开的连通分量；每类查询预热后测量 100 次。环境为 Windows、Python 3.13.5、AMD64、16 个逻辑 CPU。结果用于本地查询性能验证，不代表抽取质量。

| 查询 | P50 | P95 | 截断情况 |
|---|---:|---:|---|
| 实体搜索 | 4.39ms | 5.08ms | 无 |
| 一跳邻居 | 3.69ms | 4.68ms | 1 次达到节点上限，其余完整 |
| 高连接度节点一跳邻居 | 10.80ms | 13.29ms | 100 次均按 100 节点上限截断 |
| 最多三跳的最短路径 | 9.37ms | 89.21ms | 83 次达到五条路径上限，2 次达到搜索预算，15 次完整 |
